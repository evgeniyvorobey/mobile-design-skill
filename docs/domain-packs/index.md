# Domain Packs

Domain packs are compact mobile-design playbooks for recurring product categories. They help the skill move from generic mobile UI advice to domain-aware hierarchy, state coverage, trust language, and handoff checks.

These packs are synthetic calibration material. They do not contain proprietary case studies, copyrighted screenshots, or claims about business metrics. Treat them as recommendations and prompts for better judgment, not proof that a pattern is usable, compliant, or commercially effective.

## How To Use

1. Pick the closest domain pack before drafting a mobile screen, flow, review, or UI spec.
2. Combine it with the normal source hierarchy, platform guidance, accessibility checks, and the design-quality rubric.
3. If the product spans domains, use the strictest applicable trust/safety requirements.
4. Keep domain-specific assumptions explicit in `Unresolved assumptions` or `Open questions`.
5. Do not invent compliance, clinical, financial, marketplace, or education claims from these packs.
