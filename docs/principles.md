# Design Principles

This skill enforces a practical set of mobile UI/UX design principles.

---

## 1. Start with user task clarity

A mobile interface should make the user’s primary task obvious.

Design quality starts with:
- knowing what the user is trying to do
- reducing competing priorities on screen
- sequencing content by task relevance

A visually polished screen that obscures the main task is still a bad screen.

---

## 2. Design for context of use

Mobile use happens in constrained conditions:
- small screens
- interrupted attention
- one-handed use
- variable lighting
- motion
- network instability
- time pressure

Recommendations should reflect actual use context, not studio-perfect fantasy conditions.

---

## 3. Treat usability as effectiveness, efficiency, and satisfaction

Good UI/UX is not personal taste.

Usability must consider:
- can the user complete the task?
- can they complete it with reasonable effort?
- does the interaction remain understandable and confidence-building?

This principle is especially important when comparing competing layout or flow choices.

---

## 4. Accessibility is part of interaction design

Accessibility is not a final checklist layered on top of finished UI.

It must influence:
- navigation structure
- component behavior
- touch target sizing
- focus order
- text resizing
- readable hierarchy
- labels and semantics
- error recovery
- gesture alternatives

The skill assumes accessibility is always relevant unless the user explicitly narrows scope.

---

## 5. Typography is a usability system

Typography affects:
- scanability
- reading speed
- confidence
- emphasis
- error comprehension
- content density tolerance

Therefore typography guidance must cover:
- type roles
- hierarchy
- scaling
- weight
- line height
- spacing relationships

The skill rejects random font-size soup disguised as “creative direction.”

---

## 6. Spacing is structural, not cosmetic

Spacing helps users parse:
- grouping
- priority
- interaction zones
- density level
- tap safety
- visual rhythm

A spacing system should support repeatable decisions, not one-off nudges.

---

## 7. Platform conventions matter

Users learn patterns from platforms.

When behavior differs between iOS and Android, the skill must preserve that distinction.

Platform-aware outputs should address:
- navigation expectations
- system bars and actions
- touch and gesture norms
- component usage
- back behavior
- text and scaling behavior where relevant

Cross-platform output should share structure first, then split only where conventions materially diverge.

---

## 8. Edge states are part of the design

A design is incomplete if it only covers the happy path.

Every serious output should consider:
- empty states
- loading states
- error states
- validation states
- partial success
- recovery behavior

This is basic product reality, unfortunately.

---

## 9. Explainability matters

Strong design output should be explainable through:
- user goals
- task structure
- platform norms
- accessibility
- system consistency
- implementation constraints

If a recommendation cannot be justified beyond taste, it is not strong enough for this skill.

---

## 10. Prefer durable guidance over trends

Use long-lived guidance before trend language.

Prefer:
- official platform patterns
- standards
- maintained design systems
- operational research practices
- scalable token and component thinking

Avoid:
- vague premium/minimal/modern language
- arbitrary visual trends
- unsupported UX claims
- decorative solutions to structural problems

---

## 11. Structure output so teams can build from it

The skill should produce output that is useful in:
- design exploration
- critique
- product review
- engineering handoff
- design-system alignment
- accessibility review preparation

Useful output is:
- explicit
- scoped
- structured
- assumption-aware
- implementation-friendly
